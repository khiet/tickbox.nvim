INTRODUCTION                                                   *tickbox-intro*

tickbox.nvim draws `- [ ] task` as a hollow box and `- [x] task` as a ticked
box. Nothing else in the buffer is changed, and rendering never edits the
text. One mapping toggles the task under the cursor, or every task in a visual
range. Optional mappings start the next task on <CR>, |o| and |O|. There is no
treesitter dependency, no 'conceallevel' change and no default keymap.

Requires Neovim 0.10 or later. The default glyphs need a Nerd Font; see
|tickbox-options| for Unicode ones.

==============================================================================
INSTALL                                                      *tickbox-install*

With lazy.nvim: >lua
    { "khiet/tickbox.nvim", ft = "markdown" }
<
To pass options, add `opts = { ... }`. Extra `filetypes` also need listing in
`ft`, or the plugin stays unloaded until a markdown buffer opens.

Any other plugin manager, or |:packadd|, works too: the plugin attaches itself
on |FileType|, and calling |tickbox.setup()| is optional.

==============================================================================
OPTIONS                                    *tickbox-options* *tickbox.setup()*

require("tickbox").setup({opts})

Defaults: >lua
    require("tickbox").setup({
      filetypes = { "markdown" },
      icons = { unchecked = "󰄱", checked = "󰱒" },
    })
<
    filetypes   Filetypes to render. Replaces the default list.
    icons       Glyphs for the `unchecked` and `checked` states. Either one
                may be left out. Without a Nerd Font, try "☐" and "☑".

Each call starts from the defaults rather than the previous call's options.
Below Neovim 0.10 it raises an error naming the minimum version.

==============================================================================
COMMANDS                                         *tickbox-commands* *:Tickbox*

`:Tickbox toggle`
    Toggle the cursor line, or every task in a range, such as
    `:'<,'>Tickbox toggle`.

`:Tickbox enable`
    Render the current buffer again.

`:Tickbox disable`
    Show the raw markdown of the current buffer, until `:Tickbox enable` or
    the buffer is wiped. Toggling keeps working while rendering is disabled.

==============================================================================
MAPPING                                                      *tickbox-mapping*
                                                      *<Plug>(tickbox-toggle)*

The plugin ships no default keymap. <Plug>(tickbox-toggle) works in normal
mode, where |.| repeats it, and in visual mode, where it toggles every
selected task: >lua
    vim.keymap.set({ "n", "x" }, "<leader>t", "<Plug>(tickbox-toggle)")
<
                                                     *tickbox-fallback-recipe*
`toggle()` returns false when it did nothing, so a mapping can do something
else on other lines. This maps <leader><leader> to toggle on a task line and
otherwise switch to the alternate buffer with <C-^>, if there is one. Calling
`toggle()` directly means |.| does not repeat it: >lua
    vim.api.nvim_create_autocmd("FileType", {
      pattern = "markdown",
      callback = function(args)
        vim.keymap.set("n", "<leader><leader>", function()
          if not require("tickbox").toggle() and vim.fn.bufnr("#") ~= -1 then
            vim.cmd.normal({ vim.keycode("<C-^>"), bang = true })
          end
        end, { buffer = args.buf })
      end,
    })
<

CONTINUING A LIST                                           *tickbox-continue*
                                                     *<Plug>(tickbox-newline)*
                                                  *<Plug>(tickbox-open-below)*
                                                  *<Plug>(tickbox-open-above)*

Three more mappings, also unbound, start a new unchecked task with the
indentation and marker of the task line under the cursor. Off a task line
they act as plain keys.

<Plug>(tickbox-newline)       Insert mode. Like <CR>; on an empty task it
                              clears the line instead, ending the list.
<Plug>(tickbox-open-below)    Normal mode. Like |o|.
<Plug>(tickbox-open-above)    Normal mode. Like |O|.

Ordered tasks such as `1. [ ]` are not continued. |u| undoes the new task
together with the text typed after it, but |.| does not repeat the task
prefix. The new line ignores 'formatoptions', so a plugin that continues lists
itself, like vim-markdown, does not add a second marker. Bind them per
buffer, since <CR>, |o| and |O| are too common to map everywhere: >lua
    vim.api.nvim_create_autocmd("FileType", {
      pattern = "markdown",
      callback = function(args)
        vim.keymap.set("i", "<CR>", "<Plug>(tickbox-newline)",
          { buffer = args.buf })
        vim.keymap.set("n", "o", "<Plug>(tickbox-open-below)",
          { buffer = args.buf })
        vim.keymap.set("n", "O", "<Plug>(tickbox-open-above)",
          { buffer = args.buf })
      end,
    })
<
A buffer-local <CR> hides a completion plugin's global one. If yours confirms
with <CR>, check its menu first. For nvim-cmp, use this in place of the <CR>
line in the callback above: >lua
    vim.keymap.set("i", "<CR>", function()
      if require("cmp").visible() then
        return "<Cmd>lua require('cmp').confirm()<CR>"
      end
      return "<Plug>(tickbox-newline)"
    end, { buffer = args.buf, expr = true, remap = true })
<
==============================================================================
LUA API                                                          *tickbox-api*

`buf` defaults to the current buffer.

setup({opts})
    See |tickbox.setup()|.

toggle()                                                    *tickbox.toggle()*
    Toggle the cursor line. Returns true if it edited the line, false on a
    non-task line, a fenced line, in a filetype that is not configured or in a
    nomodifiable buffer.

toggle_range({first}, {last})                         *tickbox.toggle_range()*
    Toggle every task on these 1-indexed, inclusive lines as one undo step.
    Returns true if any line changed.

enable({buf})                                               *tickbox.enable()*
    Clear `disable`. A filetype that is not configured still does not render.

disable({buf})                                             *tickbox.disable()*
    Stop rendering the buffer.

is_enabled({buf})                                       *tickbox.is_enabled()*
    Whether the buffer renders: its filetype is configured and it is not
    disabled.

HIGHLIGHT GROUPS                                          *tickbox-highlights*

                                                            *TickboxUnchecked*
TickboxUnchecked    Unchecked glyph. Links to `Comment` by default.

                                                              *TickboxChecked*
TickboxChecked      Checked glyph. Links to `DiagnosticOk` by default.

Both are defined with `default = true`, so a colorscheme or your own
definition wins.

==============================================================================
WHAT COUNTS AS A TASK                                          *tickbox-tasks*

A line with optional indentation, a marker (`-`, `*`, `+`, or digits followed
by `.` or `)`), spaces, `[ ]`, `[x]` or `[X]`, and then at least one space. So
`- [ ]x` and a line ending in `- [ ]` stay raw.

Lines inside fenced code blocks, opened by three or more backticks or tildes,
are left alone. Fence matching is deliberately simpler than CommonMark:

- An opening fence at any indentation counts, so indented code holding a bare
  fence opens one.
- A fence may open right after a list marker. A line that starts with a
  marker never closes a fence.
- The end of a list item does not close its fence.

In insert and replace mode the cursor line shows its raw text, so the overlay
never covers what you are editing.
