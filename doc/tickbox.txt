INTRODUCTION                                                   *tickbox-intro*

tickbox.nvim draws `- [ ] task` as a hollow box and `- [x] task` as a ticked
box, with `[/]` for in progress and `[-]` for cancelled. Nothing else in the
buffer is changed, and rendering never edits the text. One mapping toggles the
task under the cursor, or every task in a visual range, and another cycles it
through the four states. Optional mappings start the next task on <CR>, |o|
and |O|. There is no default keymap. No treesitter dependency or
'conceallevel' change either, once `links` and `compact` are both off.

Requires Neovim 0.10 or later. The default glyphs need a Nerd Font; see
|tickbox-options| for Unicode ones.

==============================================================================
INSTALL                                                      *tickbox-install*

With lazy.nvim: >lua
    { "khiet/tickbox.nvim", ft = "markdown" }
<
To pass options, add `opts = { ... }`. Extra `filetypes` also need listing in
`ft`, or the plugin stays unloaded until a markdown buffer opens.

Any other plugin manager, or |:packadd|, works too: the plugin attaches itself
on |FileType|, and calling |tickbox.setup()| is optional.

==============================================================================
OPTIONS                                    *tickbox-options* *tickbox.setup()*

require("tickbox").setup({opts})

Defaults: >lua
    require("tickbox").setup({
      filetypes = { "markdown" },
      icons = {
        unchecked = "󰄱",
        in_progress = "󰡖",
        checked = "󰱒",
        cancelled = "󰅗",
      },
      progress = false,
      auto_check_parent = false,
      fold = false,
      links = true,
      compact = true,
    })
<
    filetypes   Filetypes to render. Replaces the default list.
    icons       Glyphs for each state, see |tickbox-states|. Any of them may
                be left out. Without a Nerd Font, try "☐", "◐", "☑" and "☒".
    progress    Show `done/total` at the end of every parent task and heading
                line with at least one counted task, in |TickboxProgress|.
                See |tickbox-progress|.
    auto_check_parent
                After a toggle, cycle or set, check an ancestor whose counted
                descendants are all checked, and uncheck a checked ancestor
                with a descendant that is not. See |tickbox-progress|.
    fold        Fold headings that have tasks in attached buffers. Off, the
                plugin leaves every fold option untouched. See |tickbox-fold|.
    links       Draw inline links on task lines as their label, in
                |TickboxLink|. `links = false` draws them raw. See
                |tickbox-links|.
    compact     Draw the box one space from the task's text. `compact = false`
                pads the box to the prefix's width, so the text stays in its
                raw column. See |tickbox-compact|.

`links` and `compact` both hide text, which changes 'conceallevel',
'concealcursor' and the buffer's treesitter highlighter, see |tickbox-links|.
With both `false` the plugin leaves all three alone.

Each call starts from the defaults rather than the previous call's options.
Below Neovim 0.10 it raises an error naming the minimum version.

==============================================================================
TASK STATES                                                   *tickbox-states*

    Text         State          Icon key       Highlight ~
    `[ ]`          unchecked      `unchecked`      |TickboxUnchecked|
    `[/]`          in progress    `in_progress`    |TickboxInProgress|
    `[x]` `[X]`      checked        `checked`        |TickboxChecked|
    `[-]`          cancelled      `cancelled`      |TickboxCancelled|

Toggling is a done/not-done switch: a checked task becomes `[ ]` and every
other task becomes `[x]`. Cycling walks `[ ]`, `[/]`, `[x]`, `[-]` and back to
`[ ]`; `[X]` cycles as checked. Setting goes straight to the state you name
and is not a toggle: a task already in that state is left alone, and `[X]`
stays as written when set to `checked`.

==============================================================================
PROGRESS AND PARENTS                                        *tickbox-progress*

Both are off by default; see the `progress` and `auto_check_parent` options.

A task's descendants are the task lines after it with a greater indentation,
up to the first non-blank line indented the same or less. Blank lines and
deeper non-task lines do not end them. A tab counts to the next multiple of
four columns.

A heading (`#` to `######`) holds every task until the next heading of the
same or a higher level, so `## A` includes the tasks under a `### B` inside
it.

Counts cover all descendants, not only direct children. `done` is checked
tasks and `total` is unchecked, in-progress and checked ones; cancelled tasks
are left out, and a total of 0 shows nothing. Counts follow |:Tickbox|
`disable` and `enable` like the icons, and stay visible on the line being
typed.

With `auto_check_parent`, the change walks up through every ancestor. It never
changes a task's descendants, never touches a cancelled ancestor, and never
uses headings. A toggle, cycle or set and the parents it updates are one undo
step, and a range updates parents once after all its edits, leaving the tasks
in the range as the range set them.

Fenced lines are ignored, as everywhere else.

==============================================================================
FOLDING                                                         *tickbox-fold*

`fold = true` sets 'foldmethod', 'foldexpr', 'foldtext' and 'foldlevel' on
attached buffers. Folds start open, and there are no new keymaps: native |za|,
|zc|, |zM| and |zR| work.

A heading folds if it has at least one task under it, by the rules in
|tickbox-progress|, including one with only cancelled tasks. Nested headings
fold too. A heading with no tasks has no fold of its own, and folds with its
parent if it has one.

A fold runs from the heading through the line before the next heading of the
same or a higher level, prose and trailing blank lines included. Fenced lines
are ignored, and only `#` to `######` headings fold.

Folds follow edits: the first task under a heading makes it foldable, and
removing its last task removes the fold, without closing anything you closed.

A closed heading shows its own text and highlighting rather than a fold
summary, followed by its count when `progress` is on. The rest of the line
takes the `fold` item of 'fillchars'.

A toggle, cycle or set with the cursor on a closed heading does nothing and
returns false, as on any non-task line. A visual selection over a closed fold
acts on the tasks in it.

COMPACT BOX                                                  *tickbox-compact*

`compact`, on by default, draws the box one space from the task's text:
>markdown
    - [x] FUS-1: parent task
      - Priority: High
      - [ ] child task
<
draws as >
    󰱒 FUS-1: parent task
      - Priority: High
      󰄱 child task
<
The icon draws at the start of the prefix and the rest of the prefix is
hidden, so lines indented under a task line up with its text. One rule covers
every task: whatever part of the prefix the icon does not cover is hidden.
That includes ordered tasks, nested tasks and icons wider than one cell; an
icon as wide as the prefix hides nothing. The buffer text does not change, and
no other line changes appearance.

`compact = false` draws the padded box: the icon, then spaces to the width of
the prefix, so the text stays in its raw column. The padded box also draws
wherever Neovim would show the hidden text, so no raw `[x]` appears beside the
icon:

- on every line of a visual selection, cursor line included
- in a window at 'conceallevel' 0 or 1
- in a buffer that does not qualify, see below

In normal and command mode the cursor line stays compact. The line being typed
on shows its raw text as always.

In normal mode the cursor treats the compact box as one character: it rests on
the prefix only at its first byte, the box. For `- [x] foo`:

- |h| from `f` lands on the space, and again on the box; |b|, |ge| and |F|
  from the text land on the box
- |l| from the box lands on the space, and again on `f`
- |w|, |W| and |e| from the box land on `f`, or on the space when the task has
  no text
- |j| and |k| onto the hidden prefix settle on the box

On a single-digit ordered task such as `1. [ ] foo`, |w| from the box lands on
the space and takes a second press to reach the text. Operators such as |dw|
and |x| still act on the raw bytes. The cursor goes anywhere in the prefix in
visual mode, on the line being typed on, and wherever the padded box is drawn.

Hiding text works as it does for `links`: see |tickbox-links| for the window
options this sets, the highlighter it replaces and which buffers qualify. A
buffer needs a treesitter highlighter. Neovim 0.12 starts one for markdown by
itself; Neovim 0.10 and 0.11 do not, so there the box stays padded unless you
start one. A window already at level 2 or 3 keeps its options and its
highlighter and gets the compact box.

These costs come with hiding text:

- Neovim wraps on the raw width, so a task line wraps 4 cells early.
- The text shifts 4 cells right when a line becomes the line being typed on or
  enters a visual selection.

==============================================================================
LINKS                                                          *tickbox-links*

`links`, on by default, draws an inline link on a task line as its label:
>markdown
    - [ ] review [ABC-123](https://example.com/ABC-123) today
<
draws as `review ABC-123 today`, with the label in |TickboxLink|. The buffer
text does not change. No mapping is added: |gx| opens the URL as usual, from
the label, a bracket or the hidden URL. That is tested on Neovim 0.12, which
reads the URL from treesitter; earlier versions are untested.

Only the text after a task's prefix counts. Plain bullets, prose, headings,
fenced lines and indented lines under a task stay raw, even with links in
them. On a task line these stay raw too: images, reference links, bare URLs,
autolinks, links in code spans, and links with an empty label or URL.

In normal and command mode the cursor line stays drawn, so lines keep their
width as the cursor moves. The line being typed on shows the raw link, which
is how you edit a URL, and so does the cursor line in visual mode. In normal
mode a motion that lands on a hidden bracket or URL carries on past it the way
it was going, so |l| and |h| step over the link as if only the label were
there. Arriving from another line, as with |j| or |k|, lands on the label. To
put the cursor on the URL, use visual or insert mode. `:Tickbox disable` shows
links raw.

Hiding text takes 'conceallevel' above 0, where Neovim's markdown queries
would also conceal every other line. So in an attached buffer with a normal
'buftype' and a treesitter highlighter, `links` or `compact` sets
`conceallevel=2` and `concealcursor=cn` on the window and replaces the
highlighter with one that uses the same query files minus their conceal
directives. A later `setup` with `links = false` and `compact = false`
restores both.

Without a treesitter highlighter, links stay raw; Neovim 0.12 starts one for
markdown by itself, and Neovim 0.10 and 0.11 do not. A window already above
level 0 keeps its options and its highlighter, because its owner already chose
conceal. It gets the labels, and at level 2 or 3 the compact box. The
highlighter belongs to the buffer, so if the buffer also shows in a window at
level 0, links stay raw there.

|:Tickbox| `disable` keeps folds, because it only stops drawing. The count
disappears with the other rendering.

==============================================================================
COMMANDS                                         *tickbox-commands* *:Tickbox*

`:Tickbox toggle`
    Toggle the cursor line, or every task in a range, such as
    `:'<,'>Tickbox toggle`.

`:Tickbox cycle`
    Cycle the cursor line, or every task in a range, such as
    `:'<,'>Tickbox cycle`.

`:Tickbox set` {state}
    Set the cursor line, or every task in a range, such as
    `:'<,'>Tickbox set cancelled`. {state} is `unchecked`, `in_progress`,
    `checked` or `cancelled`.

`:Tickbox enable`
    Render the current buffer again.

`:Tickbox disable`
    Show the raw markdown of the current buffer, until `:Tickbox enable` or
    the buffer is wiped. Toggling, cycling and setting keep working while
    rendering is disabled.

MAPPING                                                      *tickbox-mapping*
                                                      *<Plug>(tickbox-toggle)*
                                                       *<Plug>(tickbox-cycle)*
                                               *<Plug>(tickbox-set-unchecked)*
                                             *<Plug>(tickbox-set-in-progress)*
                                                 *<Plug>(tickbox-set-checked)*
                                               *<Plug>(tickbox-set-cancelled)*

The plugin ships no default keymap. <Plug>(tickbox-toggle),
<Plug>(tickbox-cycle), <Plug>(tickbox-set-unchecked),
<Plug>(tickbox-set-in-progress), <Plug>(tickbox-set-checked) and
<Plug>(tickbox-set-cancelled) work in normal mode, where |.| repeats them, and
in visual mode, where they act on every selected task as one undo step: >lua
    vim.keymap.set({ "n", "x" }, "<leader>t", "<Plug>(tickbox-toggle)")
    vim.keymap.set({ "n", "x" }, "<leader>c", "<Plug>(tickbox-cycle)")
    vim.keymap.set({ "n", "x" }, "<leader>p",
      "<Plug>(tickbox-set-in-progress)")
<
                                                     *tickbox-fallback-recipe*
`toggle()` returns false when it did nothing, so a mapping can do something
else on other lines. This maps <leader><leader> to toggle on a task line and
otherwise switch to the alternate buffer with <C-^>, if there is one. Calling
`toggle()` directly means |.| does not repeat it: >lua
    vim.api.nvim_create_autocmd("FileType", {
      pattern = "markdown",
      callback = function(args)
        vim.keymap.set("n", "<leader><leader>", function()
          if not require("tickbox").toggle() and vim.fn.bufnr("#") ~= -1 then
            vim.cmd.normal({ vim.keycode("<C-^>"), bang = true })
          end
        end, { buffer = args.buf })
      end,
    })
<

CONTINUING A LIST                                           *tickbox-continue*
                                                     *<Plug>(tickbox-newline)*
                                                  *<Plug>(tickbox-open-below)*
                                                  *<Plug>(tickbox-open-above)*

Three more mappings, also unbound, start a new unchecked task with the
indentation and marker of the task line under the cursor. Off a task line
they act as plain keys.

<Plug>(tickbox-newline)       Insert mode. Like <CR>; on an empty task it
                              clears the line instead, ending the list.
<Plug>(tickbox-open-below)    Normal mode. Like |o|.
<Plug>(tickbox-open-above)    Normal mode. Like |O|.

The new task is `[ ]` whatever the state of the one under the cursor.
Ordered tasks such as `1. [ ]` are not continued. |u| undoes the new task
together with the text typed after it, but |.| does not repeat the task
prefix. The new line ignores 'formatoptions', so a plugin that continues lists
itself, like vim-markdown, does not add a second marker. Bind them per
buffer, since <CR>, |o| and |O| are too common to map everywhere: >lua
    vim.api.nvim_create_autocmd("FileType", {
      pattern = "markdown",
      callback = function(args)
        vim.keymap.set("i", "<CR>", "<Plug>(tickbox-newline)",
          { buffer = args.buf })
        vim.keymap.set("n", "o", "<Plug>(tickbox-open-below)",
          { buffer = args.buf })
        vim.keymap.set("n", "O", "<Plug>(tickbox-open-above)",
          { buffer = args.buf })
      end,
    })
<
A buffer-local <CR> hides a completion plugin's global one. If yours confirms
with <CR>, check its menu first. For nvim-cmp, use this in place of the <CR>
line in the callback above: >lua
    vim.keymap.set("i", "<CR>", function()
      if require("cmp").visible() then
        return "<Cmd>lua require('cmp').confirm()<CR>"
      end
      return "<Plug>(tickbox-newline)"
    end, { buffer = args.buf, expr = true, remap = true })
<
==============================================================================
LUA API                                                          *tickbox-api*

`buf` defaults to the current buffer.

setup({opts})
    See |tickbox.setup()|.

toggle()                                                    *tickbox.toggle()*
    Toggle the cursor line. Returns true if it edited the line, false on a
    non-task line, a fenced line, in a filetype that is not configured or in a
    nomodifiable buffer.

toggle_range({first}, {last})                         *tickbox.toggle_range()*
    Toggle every task on these 1-indexed, inclusive lines as one undo step.
    Returns true if any line changed.

cycle()                                                      *tickbox.cycle()*
    Cycle the cursor line. Returns what |tickbox.toggle()| would.

cycle_range({first}, {last})                           *tickbox.cycle_range()*
    Cycle every task on these lines as one undo step. Returns what
    |tickbox.toggle_range()| would.

set({state})                                                   *tickbox.set()*
    Set the cursor line to "unchecked", "in_progress", "checked" or
    "cancelled". Returns true if it edited the line, false if the task is
    already in that state or in the cases where |tickbox.toggle()| returns
    false. Raises an error on an unknown state.

set_range({state}, {first}, {last})                      *tickbox.set_range()*
    Set every task on these lines as one undo step. Tasks already in the state
    are left alone. Returns true if any line changed. Raises an error on an
    unknown state.

enable({buf})                                               *tickbox.enable()*
    Clear `disable`. A filetype that is not configured still does not render.

disable({buf})                                             *tickbox.disable()*
    Stop rendering the buffer.

is_enabled({buf})                                       *tickbox.is_enabled()*
    Whether the buffer renders: its filetype is configured and it is not
    disabled.

HIGHLIGHT GROUPS                                          *tickbox-highlights*

                                                            *TickboxUnchecked*
TickboxUnchecked    Unchecked glyph. Links to `Comment` by default.

                                                           *TickboxInProgress*
TickboxInProgress   In-progress glyph. Links to `DiagnosticWarn` by default.

                                                              *TickboxChecked*
TickboxChecked      Checked glyph. Links to `DiagnosticOk` by default.

                                                            *TickboxCancelled*
TickboxCancelled    Cancelled glyph. Links to `Comment` by default.

                                                          *TickboxCheckedText*
TickboxCheckedText  Text of checked tasks, after the box. Has no attributes
                    by default, so checked lines look unchanged until you
                    define it. To strike done tasks through and dim them
                    like comments: >lua
    local comment = vim.api.nvim_get_hl(0, { name = "Comment", link = false })
    vim.api.nvim_set_hl(0, "TickboxCheckedText",
      vim.tbl_extend("force", comment, { strikethrough = true }))
<
                    A `link` overrides every other attribute, so
                    `{ strikethrough = true, link = "Comment" }` would not
                    strike anything through.

                                                             *TickboxProgress*
TickboxProgress     `done/total` counts, see |tickbox-progress|. Links to
                    `Comment` by default.

                                                                 *TickboxLink*
TickboxLink         The label of a link drawn by `links`, see |tickbox-links|.
                    Links to `Underlined` by default. Combines with
                    |TickboxCheckedText| on checked tasks.

All are defined with `default = true`, so a colorscheme or your own
definition wins.

==============================================================================
WHAT COUNTS AS A TASK                                          *tickbox-tasks*

A line with optional indentation, a marker (`-`, `*`, `+`, or digits followed
by `.` or `)`), spaces, `[ ]`, `[/]`, `[x]`, `[X]` or `[-]`, and then at least
one space. So `- [ ]x` and a line ending in `- [ ]` stay raw.

Lines inside fenced code blocks, opened by three or more backticks or tildes,
are left alone. Fence matching is deliberately simpler than CommonMark:

- An opening fence at any indentation counts, so indented code holding a bare
  fence opens one.
- A fence may open right after a list marker. A line that starts with a
  marker never closes a fence.
- The end of a list item does not close its fence.

In insert and replace mode the cursor line shows its raw text, so the overlay
never covers what you are editing.
